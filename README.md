# 去 AI 味 · 小程序前端

微信小程序前端，通过 `wx.cloud.callContainer` 调用云托管上的后端服务（仓库：
`wxcloud-django-tools`）。**这是一个独立项目**，不依赖后端仓库里的任何文件，
两边只靠 HTTP 接口契约耦合。

## 三步跑起来

### 1. 用开发者工具导入**仓库根目录**（不是 `miniprogram/`）

`project.config.json` 在仓库根目录，里面写着 `"miniprogramRoot": "miniprogram/"`，
所以导入时选这个仓库的根目录即可，开发者工具会自己去 `miniprogram/` 找 `app.json`。

### 2. 改两处配置

**`miniprogram/config.js`**（这是唯一需要改的代码文件）：

```js
CLOUD_ENV: 'prod-xxxx',    // 云托管「环境ID」（不是环境名）
SERVICE_NAME: 'deai-api',  // 云托管服务名
```

- 环境ID：微信云托管控制台 → 环境设置 → 环境ID
- 服务名：控制台 → 服务管理 → 服务列表 → 服务名称

没改这两项的话，首页会直接显示一张「还差一步就能用了」的提示卡，不会甩一个看不懂的报错。

**`project.config.json`** 里的 `appid`：换成你自己的小程序 AppID。

### 3. 确认基础库版本

小程序后台 → 设置 → 基础库最低版本 ≥ **2.23.0**（`wx.cloud.callContainer` 的要求）。
开发者工具里可以在「详情 → 本地设置 → 调试基础库」切换。

> 不需要配「服务器域名」：`callContainer` 走微信内网链路，免域名校验、免备案。
> 也不需要 `npm install`：项目零依赖，直接编译。

## 目录结构

```
project.config.json            开发者工具的项目配置（miniprogramRoot 指向下面）
miniprogram/                   ← 小程序根目录（只有这里面的东西会被编译/上传）
  app.js / app.json / app.wxss 小程序入口、两个 tab、全局样式
  config.js                    ★ 唯一需要改的文件
  utils/api.js                 云托管调用层（唯一出口，页面不直接碰 wx.cloud）
  utils/store.js               本地历史记录（索引 + 明细分离）+ 参数偏好
  utils/format.js              纯函数：字数、时间、报告加工、选项构造
  components/result-modal/     结果弹窗（首页和历史页共用）
  pages/index/                 输入 → 去 AI 味
  pages/history/               历史记录
scripts/selfcheck.js           Node 自检脚本（在小程序根目录之外，不会被编译）
```

> ⚠️ `scripts/selfcheck.js` 是 **Node 脚本**（用 `require('path')`、`process.exit`、
> `async/await`），这些在小程序运行时都不存在。它必须待在 `miniprogram/` **外面**——
> 放在里面会被开发者工具当成小程序代码去编译，属于必错的写法。

## 自检

小程序代码没法在命令行里跑单测（`Page` / `Component` / `wx` 都是运行时的东西），
但容易出错的部分其实都是纯逻辑。所以把 `wx.*` 桩掉，用普通 node 验一遍：

```bash
node scripts/selfcheck.js
```

覆盖：字数统计、历史记录增删改查与 50 条淘汰、弹窗记录归一化（含 AI 失败时的规则版兜底）、
参数偏好、场景/强度选项构造、请求报文与信封拆解、轮询容错、错误码映射。

它不会碰 `config.js` 里的真实配置（只在内存里改），也不会发任何网络请求。

## 功能

**首页**

- 输入框最多 **1000 字**（`textarea` 的 `maxlength` 直接卡住，不会等提交才报错），右下角实时计数，到顶变红
- 输入框自带长按复制/粘贴，另外给了显式的「粘贴 / 复制 / 清空」三个按钮
- **场景 / 强度选择器**：场景 4 个（通用 / 小红书 / 学术 / 公文），强度 3 档（轻度 / 中度 / 重度）
- 点「开始去 AI 味」调用后端，结果显示在**底部弹窗**里，一键复制结果（也能复制原文）
- 弹窗里可以展开看「AI 味体检」：分数、等级、命中的具体词句和修改建议
- 次数用完时，页面会显示「明天 0 点恢复」，后端返回的错误文案也带了同样的说明

**历史记录**

- 每次改写自动存一条（原文 + 规则版 + AI 版 + 体检报告）
- 点开看详情，长按删除单条，右上角清空
- **只存在本机**，不上传服务端

## 依赖的后端接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/skills` | 拉默认 skill / 场景，前端不写死选项 |
| GET | `/api/quota` | 今日剩余次数 + `resetsAt`（下次归零时刻） |
| POST | `/api/rewrite` | 创建改写任务（混合模式：优先同步返回，超时转轮询） |
| GET | `/api/task/<taskId>` | 轮询任务结果 |

> 另外两个接口**当前没有用到**：`/api/health`（部署探活，用浏览器或 curl 看就行）、
> `/api/auth/login`（手机号授权，见下方说明）。

## 几个设计取舍

**为什么结果用弹窗而不是 `wx.showModal`**

`wx.showModal` 只能显示纯文本，用户**没法选中、没法复制**，而「把结果复制走」
正是这个小程序唯一的出口动作。所以自己写了一个底部弹窗组件。

**为什么场景/强度的选项不写死在前端**

选项和中文名都从 `/api/skills` 拉：后端加一个场景（比如「公众号」），前端不用改一行代码
就多一个按钮。中文名则由前端 `format.js` 的映射表补上——后端返回的是 key，
映射表里没有的 key 会直接显示原始字符串，不会渲染成空白。

顺带两个细节：

- 场景列表优先用「当前 skill 自己支持的 `scenes`」，而不是全局并集。将来某个 skill
  只支持一部分场景时，用它才不会出现「选了但后端不认」的选项。
- 拉的接口挂了就把整张选择器卡片隐藏，用默认参数照样能改写，而不是写死一份前端副本。

**为什么记住上次选的场景/强度**

这是个会反复用的工具，每次都重选一遍很烦。选择存在本地（`deai_prefs_v1`），
但恢复时会**校验它是否还在后端的候选列表里**——如果后端下线了那个场景，
本地存的旧值会被丢弃并退回默认值，不会发一个后端不认的参数出去。

**为什么轮询里单次失败不判死**

小程序切到后台 **5 秒后**，正在进行的请求会被系统直接杀掉，报 `fail interrupted`。
如果把它当失败处理，用户切出去回个消息回来就发现「改写失败了」，但后端其实还在跑。
所以轮询遇到传输层错误会继续重试，只有总时长超了才判失败（而且超时前还会补查最后一次）。

**为什么把 taskId 存本地**

同理：切后台导致 APP 被回收后，重进小程序会重新执行 `onLaunch`。把 taskId 存一份，
回来时能接着取结果，不至于白等一场。

**为什么历史记录拆成「索引 + 明细」两个 storage key**

小程序单个 storage key 上限 1MB。一条记录含原文 + 两版结果 + 体检报告，
50 条塞一个 key 必然超限。所以索引只放时间/分数/摘要（列表页读它），明细一条一个 key，淘汰时一起删。

**为什么界面上没有「登录 / 授权手机号」入口**

次数是按 openid 算的，而 openid 由云托管在服务端自动注入——**用户什么都不用做**
就有每天 10 次。所以不需要登录，也没有「登录后更多次数」这回事。

手机上放「授权手机号」按钮曾经是为了把次数从 5 次提到 10 次，现在次数已经统一，
那个按钮就撤掉了：该能力**每次成功调用收费 0.03 元**，而且只对「非个人主体且已认证」
的小程序开放，留着它只会让用户白点、让你白花钱。

后端 `/api/auth/login` 仍然保留（它是整套体系里唯一「用户主动做过、且微信背书」的动作，
以后做账号体系用得上），需要时可以把它接回来。

## 常见报错对照

| 现象 | 原因 |
| --- | --- |
| `errCode -601027` Environment not found | `CLOUD_ENV` 填错了（要填环境**ID**，不是环境名） |
| `errCode -601031` | `SERVICE_NAME` 填错，或该服务还没有线上版本 |
| `errCode -601034` | 这个小程序没开通该云托管环境（也没有资源复用权限） |
| `Cloud API isn't enabled` | `wx.cloud.init` 还没完成，`utils/api.js` 会自动重试 3 次；一直报就检查基础库版本 |
| 一直「正在改写…」 | 后端模型密钥没配，或模型服务连不上；用 `/api/health` 看 `llmConfigured` |
| `QUOTA_EXCEEDED` | 当天次数用完，北京时间 0 点自动恢复 |

## 已知限制

- **次数按 openid 记在后端**，换微信号才会重置；清小程序缓存没用（这是有意设计）
- **每人每天的次数由后端 `DEAI_DAILY_QUOTA` 决定**（默认 10），前端不写死；
  界面上显示的 `{{quota.limit}}` 就是后端返回的真实值
- **历史记录只有本机**：换手机或删小程序就没了，也不会多端同步
- 弹窗里的体检详情最多列 8 条命中，超过只显示条数
